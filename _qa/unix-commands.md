## ラウンド 1

### ❓ Q1 — 【最重要】生徒はどこでコマンドを打つのか

生徒の端末は **Windows** です。Windows には Unix コマンドが標準で入っていないため、
**何かしらの実行環境が必要**です。ここが決まらないと「手順」が1行も書けません。

- **A. Git Bash** ← 推奨
  Git for Windows に付属するシェル。`ls` `cd` `grep` `chmod` などが一通り動きます。
  **Java / Spring Boot をやっているなら Git は既に入っている可能性が高い**ので、
  追加インストールなしで始められるかもしれません。管理者権限も不要です。
  弱点: 本物のLinuxではないので、`apt` などのパッケージ管理や一部コマンドは使えません。

- **B. WSL2（Windows Subsystem for Linux）**
  本物の Ubuntu が動きます。学習用途としては最も正確。
  弱点: **インストールに管理者権限が必要**で、学校PCでは許可されないことがあります。
  初回セットアップに時間がかかり、90分の授業がセットアップだけで終わる危険があります。

- **C. ブラウザで動くオンライン環境**（Google Cloud Shell など）
  インストール一切不要。ただしGoogleアカウントでのログインが要ります。
  Classroom を使っているなら生徒は全員Googleアカウントを持っているはずです。
  弱点: ネットが必須。学校のフィルタリング次第では開けない可能性。

- **D. PowerShell（Windows標準）**
  `ls` や `cd` はエイリアスとして動きますが、**これは Unix コマンドではありません。**
  `ls -la` のようなオプションは通らず、学んだ知識が Linux サーバーで通用しません。
  「Unix/Linuxコマンドの学習」としては勧められません。

➡️ **推奨: A（Git Bash）**
導入コストがほぼゼロで、学んだ知識がそのまま Linux でも通用します。
**まず「生徒のPCに Git Bash が入っているか」を確認していただきたいです。**
スタートメニューで「Git Bash」を検索すれば分かります。

**あわせて教えてください**:
1. 学校のPCに**ソフトをインストールする権限**はありますか（生徒 / 先生）
2. Git Bash は既に入っていますか

**回答:** WSL2がインストールされているので大丈夫です。

### ❓ Q2 — なぜ今 Unix コマンドを教えるのか

同じ「Unixコマンド入門」でも、**目的が変わると教える内容が全く変わります。**

- **A. 開発作業のため** — Git を使う、Spring Boot をビルドする、
  ファイルを整理する。実務で手が動くことが目的。
  → `cd` `ls` `mkdir` `cp` `mv` `rm` あたりが中心。
- **B. サーバー操作のため** — 将来 Linux サーバーにSSHで入って作業する準備。
  → 上記に加えて `chmod` `ps` `kill` `tail` などが必要。
- **C. コンピュータサイエンスの教養として** — ファイルシステムの構造、
  標準入出力、パイプという「考え方」を理解する。
  → `|` `>` `grep` `wc` の組み合わせが主役。CUIの思想そのものが題材。
- **D. とりあえず触れておきたい** — 明確な用途はまだない。

➡️ **推奨: A を軸に C を少し混ぜる**
中高生にとって「なぜマウスを使わないのか」が最大の疑問なので、
**まず手が動くようになる（A）**ことを優先し、最後にパイプを1つだけ見せて
「コマンドは組み合わせられる」という驚き（C）で終える構成が効くと考えます。
Bは、実際にサーバーを触る予定がないなら、今回は外した方が密度が上がります。

**回答:** 現状AI開発が主流になりつつある今、Claude codeのようにCLIで動かすのが当然になっています。なので最低限のUnixコマンドを覚えることで開発効率を多少上げて欲しいから。あとはコンピュータサイエンスの教養としてもある。ちなみに演習の問題はすでに完成してて、/Users/inagakitakuya/desktop/unix_lessonにある

### ❓ Q6 — 演習素材をどうやって生徒のWSL2に届けるか

生徒は `unix_lesson` ディレクトリが手元にないと演習できません。
**WSL2 特有の問題**があります。Windows 側のダウンロードフォルダは、
WSL から見ると `/mnt/c/Users/名前/Downloads/...` という長いパスになり、
**授業の冒頭がパスとの格闘で溶けます。**

- **A. GitHub Pages に `.tar.gz` を置き、コマンドで取得する** ← 推奨
  ```
  curl -O https://tsun425.github.io/explaindoc/cs/unix-commands/unix_lesson.tar.gz
  tar -xzf unix_lesson.tar.gz
  cd unix_lesson
  ```
  **2コマンドで WSL のホームに展開される**ので、`/mnt/c/...` 問題が起きません。
  しかも「コマンドで物事が進む」体験そのものが、この授業の導入になります。
  `tar` はどのLinuxにも必ず入っています（`unzip` は入っていない環境があるので zip より安全）。
  懸念: `curl` が入っていない可能性がわずかにあります。その場合は `wget` を案内します。

- **B. Classroom に zip を添付し、Windows側で展開してから `/mnt/c/...` で移動**
  確実ですが、冒頭で長いパスを打たせることになります。

- **C. コマンドで自作させる** — `mkdir` と `echo >` で生徒自身に作らせる。
  学習効果は高いが、100人の名簿は作れないので現実的ではありません。

- **D. 先生が事前に全PCに配置しておく**
  授業は最速で始まりますが、あなたの事前作業が発生します。

➡️ **推奨: A**
**授業の最初の3分が、そのまま「コマンドって便利だ」の実演になります。**
`curl` の有無だけ、事前に1台で確認していただけると確実です
（WSLで `which curl` と打つ）。

なお A を選ぶ場合、`unix_lesson` の素材を **explaindoc リポジトリに含めて公開**します。
名簿は架空の名前なので問題ないと考えていますが、念のため確認させてください。

**回答:** ここに関しては、私が横で一緒にやるので、スライドの中身に入れる必要がないです。

**（確認）名簿 `meibo.txt` の100人は架空の名前ですか？ 実在の生徒名ではないですね？**

**回答:** claudeにつくらせた架空の人物です。実在の生徒ではない。

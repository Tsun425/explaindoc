## 形式（Q1）

## 環境（Q2）★このページの前提を変える回答
**生徒によってバラバラ。** Python を触っている生徒もいれば、
Java を触っている生徒もいる。Java は **Eclipse で Web アプリの制作**。

→ Python 専用には書けない。**原則を主役**にして、
「エラーがどこに出るか」「どこを読むか」は**環境別の表**で受ける。

## エラーの読み方（Q3）
**2か所だけ読む**（回答は A）。ただし Q2 を踏まえて次のように補正した。

- 読むのは **①「種類: メッセージ」の1行** と **②自分のファイル名・行番号がある行** の2か所
- その1行が**どこにあるか**だけ環境で違う:
  - Python / Colab → かたまりの**いちばん下**
  - Java / Eclipse → かたまりの**いちばん上**（下は呼び出しの履歴）
- エラーの種類の一覧表は作らない（CLAUDE.md）。代わりに
  **英単語の読み方**（not defined / null / expected など）を置く

## ChatGPT（Q4）
**禁止しない。順番を決める。** ①エラーを読む ②自分で確かめる ③検索 ④ChatGPT。
そのうえで聞くときの貼り方を教える（やりたいこと・自分のコード・エラー全文の3点）。
「直したコードだけでなく、なぜそうなるかも説明して」と頼ませる。
コピーして動いたら、**なぜ動いたか自分の言葉で言えるか**を確かめる、を1行入れる。

## 人を呼ぶライン（Q5）★前提が重要
**質問できる相手が常にそばにいるとは限らない**、という前提で書く。
→ ページは「誰も横にいなくても、生徒だけで前に進める」ことを最優先にする。
→ 文中は特定の個人を指さず **「講師」** と書く（「先生」は使わない）。

ラインは **①〜④をやって、合計10分たっても動かなかったら講師を呼ぶ**。
内訳は 1分（読む）+ 3分（確かめる）+ 残り（検索・ChatGPT）。
呼ぶときに言うこと3つ（何をしようとしていたか / 直前に何を変えたか / エラーの1行）も書く。

> ⚠️ **10分という数字は私が置いた仮の値。** round-1 で分数の指定が無かったため。
> 授業が90分なので長すぎると感じたら変更する。ページ内の2か所を直すだけで済む。
